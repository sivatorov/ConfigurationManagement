Исправлено в версии **0.3.9.66** (Windows/WPF и Linux/Avalonia).

**Причина.** По первому пункту: после первого вызова «Блокировки приложения» окно установки
пароля закрывалось, но сама блокировка не наступала — интерфейс оставался доступным, а снять
блокировку можно было кнопкой «Отмена» или крестиком. По второму пункту: пункт «Блокировка
приложения» присутствовал только в контекстном меню базы (подменю «Администрирование»),
в «Утилитах» на Windows его не было.

**Что сделано.**

1. Первый вызов «Блокировки приложения» показывает окно установки пароля (фокус в поле
   «Новый пароль»); при отмене блокировка не запускается. После сохранения пароля сразу
   открывается окно разблокировки.
2. Окно разблокировки теперь закрывается только верным паролем: кнопка «Отмена» скрыта,
   закрытие крестиком/Esc/Alt+F4 заблокировано, при неверном пароле выводится предупреждение
   и интерфейс остаётся недоступным.
3. Пункт «Блокировка приложения» перенесён из контекстного меню базы в меню «Утилиты» —
   сразу после «Консоли администрирования серверов», не в конец списка. В подменю
   «Администрирование» контекстного меню осталась только «Блокировка сеансов».

**Проверено:** первый вызов — окно установки пароля (фокус в «Новый пароль») → «Сохранить» →
сразу окно разблокировки, главное окно недоступно; Esc/крестик блокировку не снимают;
неверный пароль — предупреждение; верный — интерфейс доступен. Пункт есть в «Утилитах»
(после «Консоли администрирования серверов») и отсутствует в контекстном меню базы.
Исправление работает на обеих платформах — Windows/WPF и Linux/Avalonia. Набор тестов (122) проходит.
