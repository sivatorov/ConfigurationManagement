# v0.3.11.0 — 2026-10-09

Windows/WPF и Linux/Avalonia.

## Исправлено

- **Автообновление: возврат самодостаточного EXE в релиз Windows (issue #358)** — автообновление с 0.3.10.3 снова работает: в релиз возвращён обязательный ассет `ConfigurationManagement.exe` — на него рассчитаны шаблон ссылки скачивания ([`GitHubReleaseService.DownloadUrlTemplate`](Configuration%20Management/Services/GitHubReleaseService.cs)) и Atom-фолбэк; при выборе ассета bare-exe теперь имеет жёсткий приоритет — ZIP-архив больше не подсовывается загрузчику автоматически; после загрузки обновление проверяется по сигнатуре: `MZ` (PE) — штатная установка, `PK` (ZIP) — из архива распаковывается `ConfigurationManagement.exe` и устанавливается он, иной контент (HTML и пр.) — файл удаляется и показывается ошибка «не удалось скачать обновление» вместо «установки» битого файла.
- **Монитор серверов 1С: детектор справки rac на платформе 8.5.4.1878 (issue #324)** — [`RacClient.LooksLikeUsageHelp`](Configuration%20Management/Services/RacClient.cs) проверяет первые 15 строк вывода (маркеры «Использование:»/«Usage:» и подстрока «rac [»), поэтому справка, начинающаяся с баннера «1C:Enterprise 8.5 Remote Administrative Client Utility …», распознаётся; при выводе справки формат `job list` не кэшируется как «рабочий» — вкладка «Задания» заполняется (или честно пуста), WARN «вывод rac не распознан» больше не повторяется на каждом опросе.
- **Скачивание версии платформы 1С: уникальные подписи дистрибутивов (issues #330, #334)** — [`PlatformDistributionOption.DisplayName`](Configuration%20Management/Services/PlatformDistributionPicker.cs) включает фактическое имя файла дистрибутива, когда вариантов одного типа может быть несколько: уникальные строки видны сразу в обоих окнах выбора (окно «Скачивание версии платформы 1С» и диалог выбора в окне обновления), а не только после выбора файла.
- **Обновление платформы 1С: скачивание `.rar`-дистрибутивов по ссылке `version_file?…` (issue #334)** — [`OneCUpdatesService.DownloadDistributionAsync`](Configuration%20Management/Services/OneCUpdatesService.cs) сначала разрешает конечный адрес дистрибутива (страница-посредник `version_file?…` → якорь «Скачать дистрибутив» → `transfer_file`/архив) и только потом запускает многопоточную загрузку; если скачанный «файл» оказался HTML-документом, он не сохраняется — загрузка возвращается к однопоточному резолвингу, при неудаче в журнал пишется признак «страница-посредник не разрешилась в файл» и URL.
- **Проверка обновлений и цепочки обновлений конфигурации (issue #352)**:
  - **кнопка «Скачать»: выбор дистрибутива** — для релиза с `.cf`-дополнительным файлом скачивание больше не заканчивается WARN «В ответе не найдена ссылка на дистрибутив»: [`OneCUpdatesService.GetReleaseFileChoicesAsync`](Configuration%20Management/Services/OneCUpdatesService.cs) открывает страницу файлов версии и предлагает выбор «Дистрибутив обновления» / «Полный дистрибутив»; один вариант скачивается сразу, расширение имени сохранения берётся из выбранного файла;
  - **запоминание папки сохранения цепочки + кнопка «Открыть»** — выбранный каталог запоминается в настройках ([`AppSettings.UpdateChainFolder`](Configuration%20Management/Models/AppSettings.cs)), при следующем скачивании цепочки диалог открывается в нём; над таблицей цепочки показывается путь и кнопка «Открыть»;
  - **диалог «Попробовать ещё раз?»** — при ошибках скачивания цепочки вместо простого предупреждения открывается окно с вопросом повтора и 60-секундным обратным отсчётом; «Да» докачивает только недостающее ([`UpdateChainDownloadPlanner.SelectPendingSteps`](Configuration%20Management/Services/UpdateChainDownloadPlanner.cs)).
- **Меню закладок: детерминированное восстановление текущей строки (issue #356)** — признак «меню закрыто кликом по пункту» вычисляется в момент клика по попапу, а не нестабильным hit-test при закрытии: подсветка/выделение текущей строки дерева восстанавливается после закрытия меню закладок и контекстного меню выбором пункта (регрессия #340) — WPF ([`MainWindow.Hotkeys.cs`](Configuration%20Management/Views/MainWindow.Hotkeys.cs)) и Avalonia ([`MainWindow.Avalonia.Events.cs`](Configuration%20Management/Views/MainWindow.Avalonia.Events.cs)).
- **Локализация окна «Замена строк подключения» (issue #357)** — ключи `ConnectionReplace.FieldLabel`/`ScopeLabel`/`ModeLabel` («Поле», «Область», «Режим») добавлены во встроенные словари ru/en — при устаревшем внешнем файле языка поля окна показывают значения, а не ключи; аудит всех ключей `ConnectionReplace.*` закреплён регресс-тестом.

## Как обновиться

| Платформа | Файл |
|---|---|
| Windows x64 | `ConfigurationManagement.exe` — single-file, запускается без установки (его же использует автообновление) |
| Windows x64 (архив) | `ConfigurationManagement-0.3.11.0-win-x64.zip` — внутри тот же `ConfigurationManagement.exe` |
| Linux x64 | пакет `configuration-management_0.3.11.0_amd64.deb` |
| Контрольные суммы | `SHA256SUMS.txt` |

Просто замените предыдущую версию новой — настройки и данные не затрагиваются.
