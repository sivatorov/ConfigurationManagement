Реализовано в версии **0.3.9.48** на обеих платформах — Windows/WPF и Linux/Avalonia.

**Что сделано: многопоточная загрузка по HTTP Range** (по аналогии с менеджерами загрузок). Провайдеры, режущие скорость на одно соединение, больше не тормозят обновление: то, что у вас на Windows давало ~7 Мбит/с однопоточным браузером и ~80 Мбит/с менеджером с 10 потоками, теперь качается так же быстро прямо из приложения.

**Как это работает**

1. **Определение размера и поддержки Range** — при старте загрузки приложение отправляет запрос `GET` с `Range: bytes=0-0`. Ответ `206 Partial Content` подтверждает поддержку Range и содержит полный размер файла.
2. **Разбиение на сегменты** — файл делится на **до 8 сегментов** (не больше размера файла; минимальный сегмент ~1 МБ — на маленьких файлах многопоточность бесполезна). Каждый сегмент скачивается отдельным соединением с заголовком `Range: bytes=start-end` в свой временный файл `<dest>.<i>.part`.
3. **Докачка и устойчивость** — каждый `.part` при обрыве продолжает качаться со своего места (Range от текущего размера части), до 12 попыток на сегмент с растущей паузой. Сбой одного сегмента отменяет остальные.
4. **Склейка** — после успеха всех сегментов части последовательно собираются в итоговый файл, и проверяется, что его размер равен полному размеру файла.
5. **Прогресс** — агрегированный (сумма скачанного по всем сегментам / общий размер), публикуется не чаще раза на целый процент. Окна прогресса и автообновление работают как раньше, интерфейс события `DownloadProgressChanged` не менялся.

**Fallback (безопасность)**

При любом сбое параллельного режима загрузка не ломается, а автоматически переходит на прежний однопоточный путь с докачкой:

- сервер не поддерживает Range (отвечает `200` вместо `206`);
- размер файла неизвестен (нет `Content-Length` / `Content-Range`);
- файл слишком мал (меньше ~1 МБ);
- ошибки сегментов после всех повторов или несовпадение размера после склейки.

То есть на серверах/прокси без поддержки Range поведение остаётся ровно таким, как раньше.

**Число потоков**

До **8 одновременных соединений** (константа `DefaultMaxParallelism`), сегменты докачиваются независимо. Сеть не блокирует интерфейс — всё выполняется через `async/await`.

**Как проверить скорость**

1. Установите версию **0.3.9.48** и дождитесь, когда появится новая версия (или нажмите «Проверить обновления» во вкладке «О программе»).
2. При скачивании обновления наблюдайте прогресс-бар: на вашем соединении (Windows) скорость должна приблизиться к максимуму линии, как у менеджера загрузок с несколькими потоками (в вашем случае ~80 Мбит/с вместо ~7 Мбит/с).
3. При желании сравните с тем же файлом, скачанным браузером в одно соединение, — разница покажет эффект многопоточной загрузки.

Если после обновления скорость по-прежнему низкая — напишите, пожалуйста: возможно, провайдер/прокси ограничивает и суммарную ширину канала, тогда поможем подобрать число потоков под вашу сеть.
