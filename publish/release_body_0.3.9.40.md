## [0.3.9.40] — 2026-09-24

Исправлен открытый issue [#277](https://github.com/sivatorov/ConfigurationManagement/issues/277).

### Исправления

- **Сохранение кодировки «UTF-8 (BOM)» при перезаписи `ibases.v8i` ([#277](https://github.com/sivatorov/ConfigurationManagement/issues/277))** —
  после правки базы файл переписывался в кодировку по умолчанию без метки порядка, хотя исходный
  файл стартера 1С был сохранён как «UTF-8 (BOM)». Теперь кодировка определяется по байтовой метке
  порядка (BOM) перед чтением и сохраняется при записи.
  1. **Определение кодировки по BOM** — новый метод `IbaseEntry.DetectEncoding`: распознаются
     UTF-8 с BOM, UTF-16 LE/BE и UTF-32 LE/BE; без BOM — кодировка по умолчанию. Для нового файла
     используется UTF-8 с BOM (нативная кодировка, в которой стартер 1С создаёт `ibases.v8i`).
  2. **Чтение и запись в одной кодировке** — `IbaseEntry.Parse` читает файл в определённой кодировке,
     а `IbasesV8iExporter.Export` / `AddInfobasesToFile` пишут в той же кодировке (без потери BOM
     и кириллицы). Файл без BOM не получает BOM после экспорта.
  3. **Проверено тестами** — файл «UTF-8 (BOM)» остаётся «UTF-8 (BOM)» после полного экспорта и после
     дописывания базы, повторный экспорт идемпотентен, файл без BOM не получает метку порядка.
     Весь набор тестов (86) проходит.

- **Linux (x64)**: `ConfigurationManagement-linux-x64` (single-file, self-contained; при необходимости `chmod +x`).
