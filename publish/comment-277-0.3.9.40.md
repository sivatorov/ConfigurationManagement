Исправлено в версии **0.3.9.40**.

Причина: при перезаписи ibases.v8i файл всегда записывался в кодировку по умолчанию без метки порядка, поэтому ваш файл «UTF-8 (BOM)» превращался в «UTF-8» без BOM.

Что сделано:
- **Кодировка определяется по BOM** перед чтением и сохраняется при записи: «UTF-8 (BOM)» остаётся «UTF-8 (BOM)», кириллица не ломается. Распознаются также UTF-16 LE/BE и UTF-32 LE/BE; файл без BOM не получает BOM после экспорта.
- **Новый файл создаётся в UTF-8 с BOM** — нативная кодировка стартера 1С.
- Правило действует для полного экспорта (`Export`) и для дописывания баз (`AddInfobasesToFile`), на обеих платформах (Windows/WPF и Linux/Avalonia).

Проверено тестами: файл «UTF-8 (BOM)» после экспорта и после дописывания базы остаётся «UTF-8 (BOM)»; повторный экспорт идемпотентен; файл без BOM не получает метку порядка. Весь набор тестов (86) проходит.

Обновитесь до 0.3.9.40 и проверьте исходный файл — кодировка сохранится как была.
