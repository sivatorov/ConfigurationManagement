Исправлено в версии **0.3.11.0** (Windows/WPF и Linux/Avalonia).

**Что было.** После закрытия меню закладок (и контекстного меню) кликом по пункту подсветка/выделение текущей строки дерева восстанавливалась «через раз» — механизм стабилизации опирался на нестабильный hit-test (`Mouse.DirectlyOver`) в момент закрытия попапа.

**Как исправлено:**

1. **Детерминированное определение факта закрытия кликом** — признак «меню закрыто кликом по пункту» теперь фиксируется в момент клика по пункту меню, а не вычисляется через нестабильный `Mouse.DirectlyOver` при закрытии: WPF ([`MainWindow.Hotkeys.cs`](Configuration%20Management/Views/MainWindow.Hotkeys.cs)) и Avalonia ([`MainWindow.Avalonia.Events.cs`](Configuration%20Management/Views/MainWindow.Avalonia.Events.cs)).
2. **Контрольный второй проход стабилизации** — добавлен повторный проход восстановления подсветки/выделения текущей строки после закрытия меню, решение фиксируется в трассировке (`closedByItemClick`).

**Как проверить:**
1. Обновитесь до **0.3.11.0**.
2. Откройте меню закладок (Ctrl+B) и закройте его кликом по пункту — подсветка/выделение текущей строки дерева должны восстанавливаться каждый раз.
3. То же — с контекстным меню. Просьба проверить, что «через раз» больше не воспроизводится на нескольких десятках повторов.

Тесты: полный набор `dotnet test` зелёный (**2203**); сборка решения без ошибок.
