Исправлено в версии **0.3.9.67** (Windows/WPF).

**Что было сделано.**

В 0.3.9.58 сжатие основной строки на Windows задавалось только внешними отступами
(`Padding="0,1"` / `Margin="0,0"`), поэтому разница была малозаметна: высоту строки
определяли внутренние элементы — иконка статуса (14), иконки избранного/закрепления
(14), кнопки действий (15) и строка тегов (16), которые не масштабировались. На Linux
компактность достигалась общим коэффициентом `UiMetrics.Scale=0.8`, сжимавшим всё.

Теперь в компактном режиме на Windows сжимается вся внутренняя структура строки базы
(по образцу Linux):

1. **Иконка статуса, избранное и закрепление** — 14 → 12.
2. **Иконки кнопок действий строки** (запуск, конфигуратор, очистка кэша) — 15 → 13.
3. **Строка тегов** — бейджи тегов и кнопка «Добавить тег» 16 → 14, иконка
   «Добавить тег» 11 → 10.
4. **Бейдж горячей клавиши избранного** — минимальная ширина 16 → 14.

Вместе с уже работавшим масштабированием отступов и шрифтов
(`ThemeManager.ApplyCompactTree`: отступы ×0.7, шрифты ×0.9) основная строка теперь
визуально опускается до высоты строки группы — разница между режимами стала заметной,
как на Linux. Шапка окна и кнопки управления окном остаются компактными; обычный
(некомпактный) режим не изменён. Правки внесены только в WPF-разметку
`MainWindow.xaml` — Linux/Avalonia не затрагивалась.

**Как проверить:**

1. Установите версию **0.3.9.67**.
2. Включите компактный режим (кнопка-«сжатие» на верхней панели или
   Настройки → «Компактный режим интерфейса»).
3. Основные строки списка стали заметно ниже — по высоте равны строкам групп,
   список плотнее (включая строки с тегами).
4. Заголовок окна и кнопки управления окном по-прежнему компактные.
5. Выключите компактный режим — все размеры возвращаются к обычным;
   переключение темы и повторные переключения компактности не ломают раскладку колонок.
