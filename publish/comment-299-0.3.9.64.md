Исправлено в версии **0.3.9.64** (Windows/WPF и Linux/Avalonia).

**Причина бага.** В окне «Задание по расписанию» на Windows установки фокуса на поле
«Наименование» не было вовсе — после открытия окна фокус оставался на предыдущем элементе.
В окне «Сценарий резервирования» на Windows фокус ставился в обработчике `Loaded` синхронно,
до завершения показа окна: при открытии через `ShowDialog()` WPF передаёт фокус заголовку
или первому контролу и «съедает» его из `Loaded` — поле выглядело активным, но ввод не работал.
На Linux/Avalonia у обоих окон обработчика фокуса не было вовсе — фокус оставался на элементе,
из которого вызвано окно.

**Что сделано.** Фокус теперь ставится отложенно — после полного показа и активации окна:
- WPF: `Loaded` → `Dispatcher.BeginInvoke` с приоритетом `ApplicationIdle` → `NameBox.Focus()`;
- Avalonia: `Opened` → `Dispatcher.UIThread.Post` с приоритетом `Background` → `_nameBox.Focus()`.

При создании нового задания/сценария фокус попадает в пустое поле «Наименование», а при
редактировании существующего — имя выделяется целиком (`SelectAll`), так что новый ввод сразу
затирает прежнее значение. Логика сохранения/валидации, раскладка окон и темы не менялись.

**Проверено:** открытие «Утилиты → Задания по расписанию → Добавить» — курсор сразу в поле
«Наименование», ввод печатается без щелчка; «Сценарии резервирования → Добавить» — то же;
при «Изменить» имя выделено целиком и затирается новым вводом. Исправление работает на обеих
платформах — Windows/WPF и Linux/Avalonia. Набор тестов (122) проходит.
