Исправлено в версии **0.3.9.330** (Windows/WPF и Linux/Avalonia) — по вашему логу `app-20261008.log`:

1. **Долгое подключение — поиск rac (~4.7 с).** В логе «поиск rac занял 4717 мс»: общий поиск платформы в [`OneCPlatformLocator`](Configuration%20Management/Services/OneCPlatformLocator.cs) рекурсивно сканировал корни поиска до глубины 6 с проверкой разрядности каждой версии. Добавлен быстрый путь по стандартному макету `<корень>\1cv8\<версия>\bin` — только каталоги версий, новейшие первыми, без рекурсии и без запуска внешних проверок; тяжёлый поиск остаётся запасным для нестандартных установок. Дополнительно из длительности rac-команды в журнале больше не «выглядит» время поиска (в `4908 мс` из прошлого лога входили те же `4717 мс` поиска — сама команда `cluster list` занимала ~200 мс).

2. **«Конфигурация…» вместо имени кластера.** WPF-ComboBox с пользовательским шаблоном ModernComboBox в ряде случаев показывал выбранный элемент через `ToString()` (в логе парсер распознавал «Локальный кластер», а в поле было имя типа `Configuration_Management.ViewModels.RacClusterRow`). В [`ServerMonitorWindow.xaml`](Configuration%20Management/Views/ServerMonitorWindow.xaml) `DisplayMemberPath` заменён на явный `ItemTemplate` (паттерн ранее применён в окне сценариев), плюс добавлены `ToString()` у [`RacClusterRow`](Configuration%20Management/ViewModels/RacClusterRow.cs) и [`RacCluster`](Configuration%20Management/Models/RacModels.cs) с едиными правилами подписи («Имя (порт)», запасные хост/плейсхолдер вместо пустого или служебного имени). В Avalonia-версии монитора `ItemsSource` комбо кластеров теперь обновляется после загрузки списка (ранее задавался один раз пустым).

3. **`job list` и WARN/«ключ» в списке заданий.** По логам 2026-10-07/08 rac 8.5.4.1878 отклоняет **оба** известных формата (`--cluster=<uuid>` и `--cluster <uuid>`): «успешный» вывод в 627 симв./154 мс в логе — параллельная команда `process list`, а не job list. В [`RacClient.GetJobsAsync`](Configuration%20Management/Services/RacClient.cs) добавлен третий формат — позиционный `<uuid>` без имени параметра; рабочий формат по-прежнему кэшируется в памяти и на диске ([`RacJobListFormatStore`](Configuration%20Management/Services/RacJobListFormatStore.cs)) после первого успеха. При неуспехе всех форматов в журнал пишется один сводный WARN (а не по строке на каждую попытку), а ошибка для вкладки «Задания» просит прислать вывод `rac <адрес:порт> job list --help` — точный синтаксис платформы попадёт в следующую итерацию.

**Как проверить:** обновитесь до **0.3.9.330**, подключитесь к `localhost:27545` — поиск rac на стандартной установке занимает доли секунды, в поле подключения видно имя кластера, вкладка «Задания» заполнена (или в журнале один WARN с просьбой прислать `rac job list --help`).

Тесты: полный набор `dotnet test` зелёный (**1982**), кросс-сборка Linux (`dotnet build -p:BuildLinux=true`) без ошибок. Добавлены тесты форматов `job list` (позиционный uuid, число форматов, имена для журнала), человекочитаемой подписи `RacCluster`/`RacClusterRow` (`ToString`) и быстрого поиска rac (`FindRacIn1cv8Roots`, `IsVersionDirectoryName`).

Обе версии — **0.3.9.330** и **0.3.9.331** (в 0.3.9.331 дополнительно исправлено скачивание дистрибутивов обновлений конфигураций, issue #352) — доступны на странице релиза [v0.3.9.331](https://github.com/sivatorov/ConfigurationManagement/releases/tag/v0.3.9.331).
