Исправлено в версии **0.3.11.0** (Windows/WPF и Linux/Avalonia).

**Что было.** В релизе Windows перестал выкладываться самодостаточный `ConfigurationManagement.exe`, из-за чего автообновление с 0.3.10.3 не могло обновиться.

**Как исправлено:**

1. **Ассет `ConfigurationManagement.exe` возвращён в релиз Windows** — публикация Windows single-file EXE восстановлена: релиз содержит обязательный ассет `ConfigurationManagement.exe`, на который рассчитаны шаблон ссылки скачивания ([`GitHubReleaseService.DownloadUrlTemplate`](Configuration%20Management/Services/GitHubReleaseService.cs)) и Atom-фолбэк. ZIP-архив с exe внутри остаётся дополнительным ассетом для ручной загрузки, а не заменой.
2. **Жёсткий приоритет bare-exe при выборе ассета** — [`GitHubReleaseService.IsPlatformAsset`](Configuration%20Management/Services/GitHubReleaseService.cs): точное имя `ConfigurationManagement.exe` — первый приоритет; признак `win-x64` принимается только если bare-exe не найден и имя ассета не `.zip` — ZIP-архив больше не выбирается как ассет для Windows автоматически.
3. **Проверка сигнатуры скачанного обновления** — [`UpdateService`](Configuration%20Management/Services/UpdateService.cs) после загрузки проверяет файл: `MZ` (PE) — штатная установка как есть, `PK` (ZIP) — из архива распаковывается `ConfigurationManagement.exe` и устанавливается он, иной контент (HTML и пр.) — файл удаляется и показывается ошибка «не удалось скачать обновление» вместо установки битого файла. Защита включена и в автообновлении, и в окне «Доступна новая версия».

**Как проверить:**
1. Установите **0.3.11.0** (вручную, если текущая версия не смогла обновиться).
2. Дождитесь следующего релиза — автообновление должно найти ассет `ConfigurationManagement.exe` и обновиться без ручной загрузки ZIP.

Тесты: полный набор `dotnet test` зелёный (**2203**); сборка решения без ошибок.
