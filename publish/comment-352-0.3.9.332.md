Исправлено в версии **0.3.9.332** (Windows/WPF и Linux/Avalonia).

**Что было.** После 0.3.9.331 на реальном портале скачивание всё равно не доходило до файла: на промежуточной странице скачивания кнопка подписана «Скачать дистрибутив», но её адрес не содержит `transfer_file` и не заканчивается расширением архива — ни один из прежних признаков следующей ссылки не срабатывал.

**Как исправлено** ([`OneCUpdatesService.cs`](Configuration%20Management/Services/OneCUpdatesService.cs)):

1. **Якорные ссылки по подписи.** Новый `AddDownloadAnchorCandidates` добавляет href ссылок, подпись которых означает скачивание («Скачать дистрибутив»/«Скачать файл»/Download), кандидатом первого приоритета — даже если адрес не является архивом. HTML-сущности в href («&») декодируются, заглушки «#»/«javascript:» пропускаются.
2. **`transfer_file`/`additional_file` вне href.** Новый `FileEndpointUrlRegex` находит адреса передачи/дополнительных файлов в любом месте ответа страницы — JS-редиректы, onclick-обработчики, встроенный JSON (запасной путь, если кнопку не нашли по подписи).
3. **Расширение из query-параметров.** `GetDistributionExtension` при отсутствии распознанного расширения в пути проверяет имя файла в query-параметрах `path`/`file`/`filename` — адрес вида `transfer_file?path=…\file.cf` несёт расширение только в query, и итоговый файл теперь получает правильное расширение.

**Как проверить:**
1. Обновитесь до **0.3.9.332**, откройте «Проверка обновлений» (F9) и нажмите «Скачать» (или «Скачать цепочку»).
2. Вместо HTML-страницы должен сохраниться реальный дистрибутив с правильным расширением (`.zip`/`.rar`/`.exe`/`.7z`).
