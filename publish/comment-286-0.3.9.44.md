Реализовано в версии **0.3.9.44**.

Что сделано по пожеланию — «запланировать создание резервной копии или обновления, а лучше сценарий "Создание копии → обновление"»:

1. **Задания по расписанию** (меню «Утилиты» → «Задания по расписанию») с четырьмя типами действий:
   - **Резервная копия** — выполнение существующего сценария резервирования (DT/CF/ZIP/RAR) для выбранной базы;
   - **Обновление конфигурации ИБ** — загрузка новой конфигурации из файла `.cf` и обновление конфигурации БД (`/LoadCfg` + `/UpdateDBCfg` через конфигуратор);
   - **Копия → обновление конфигурации** — сначала резервная копия, и только при её успехе обновление конфигурации (как вы и предложили);
   - **Обновить приложение** — проверка новых версий на GitHub Releases и автообновление без диалогов.
2. **Расписание**: время («ЧЧ:ММ») и выбор дней недели (не отмечено — ежедневно), задание можно отключить. У каждого задания показывается статус последнего запуска; есть кнопка «Выполнить сейчас».
3. **Хранилище**: задания сохраняются в каталоге данных профиля (`schedules/*.task.json`), переносятся вместе с профилем.

Важное ограничение: задания выполняются, **пока приложение запущено** (как и фоновая проверка обновлений). Если в момент запуска приложения время задания уже прошло — запуск сегодня пропускается (не «догоняется»).

Реализация на обеих платформах — Windows/WPF и Linux/Avalonia. Проверено юнит-тестами (весь набор — 93 теста).

Обновитесь до 0.3.9.44, откройте «Утилиты» → «Задания по расписанию», добавьте задание (например, «Копия → обновление конфигурации») — и оно будет выполняться в указанное время, пока приложение работает.
