Исправлено в версии **0.3.11.0** (Windows/WPF и Linux/Avalonia).

**Что было.** (1) В диалоге выбора дистрибутива обновления платформы подписи строк не различались, если файлов одного типа несколько. (2) Скачивание `.rar`-дистрибутивов по ссылке `version_file?…` не доходило до файла — сохранялся HTML страницы-посредника.

**Как исправлено:**

1. **Уникальные подписи дистрибутивов** — то же исправление, что и для окна «Скачивание версии платформы 1С» ([`PlatformDistributionOption.DisplayName`](Configuration%20Management/Services/PlatformDistributionPicker.cs)): имя файла дистрибутива включается в подпись, когда вариантов одного типа может быть несколько, — уникальные строки видны сразу в диалоге выбора дистрибутива окна «Обновление платформы 1С».
2. **Скачивание `.rar`-дистрибутивов по ссылке `version_file?…`** — [`OneCUpdatesService.DownloadDistributionAsync`](Configuration%20Management/Services/OneCUpdatesService.cs) теперь сначала разрешает конечный адрес дистрибутива (страница-посредник `version_file?…` → якорь «Скачать дистрибутив» → `transfer_file`/архив) и только потом запускает многопоточную загрузку.
3. **Защита от сохранения HTML вместо файла** — если скачанный «файл» оказался HTML-документом, он не сохраняется: загрузка возвращается к однопоточному резолвингу, при неудаче в журнал пишется признак «страница-посредник не разрешилась в файл» и URL.

**Как проверить:**
1. Обновитесь до **0.3.11.0**, откройте «Обновление платформы 1С» (Ctrl+F9).
2. В диалоге выбора дистрибутива подписи строк с файлами одного типа различаются сразу.
3. Просьба перепроверить скачивание дистрибутива `setuptc64_8_3_27_2325.rar` — файл должен скачаться именно как `.rar`-архив, а не как HTML-страница.

Тесты: полный набор `dotnet test` зелёный (**2203**); сборка решения без ошибок.
