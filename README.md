# Управление конфигурациями 1С

![Версия](https://img.shields.io/badge/Версия-0.3.5.83-1F6FEB) ![.NET](https://img.shields.io/badge/.NET-10-512BD4) ![Windows/WPF](https://img.shields.io/badge/Windows-WPF-4B8BBE) ![Linux/Avalonia](https://img.shields.io/badge/Linux-Avalonia%2011-8B5CF6) ![Лицензия](https://img.shields.io/badge/Лицензия-Open%20Source-success)

> Десктопное приложение для управления информационными базами 1С:Предприятие 8.3. **Версия 0.3.5.83**

**Управление конфигурациями 1С** — это кроссплатформенное настольное приложение на платформе **.NET** (**WPF** на Windows и **Avalonia 11** на Linux), которое заменяет стандартный список баз 1С и предоставляет современный интерфейс для работы с информационными базами: запуск в режимах «1С:Предприятие» и «Конфигуратор», вкладки **Все базы / Избранное / Недавние**, иерархические группы, избранное с `Alt+1…9`, мультифильтр по тегам, очистка кеша, синхронизация с `ibases.v8i`, системный трей, светлая и тёмная темы. Одна кодовая база собирается под обе ОС: `net10.0-windows` (WPF) на Windows и `net10.0` (Avalonia) на Linux.

- **Автоматическое обновление из GitHub Releases** (Windows): при запуске программа в фоне проверяет наличие новых версий на GitHub Releases; во вкладке **«О программе»** окна настроек есть кнопка **«Проверить обновления»** для ручной проверки (сообщает, если версия актуальна). При включённой настройке **«Автоматически обновлять приложение»** (по умолчанию включена) программа при обнаружении новой версии сама скачивает self-contained `ConfigurationManagement.exe`, устанавливает его через временный помощник и перезапускается — без диалога подтверждения и участия пользователя. Если автообновление выключено — при обнаружении новой версии по-прежнему показывается диалог с кнопками **«Скачать»/«Отмена»**. Кнопка «Проверить обновления» всегда показывает результат/диалог и не устанавливает обновление молча. Проверка при запуске и автообновление настраиваются в окне «Настройки» → «Поведение приложения». Если основной GitHub Releases API недоступен (например, `api.github.com` не отвечает, хотя `github.com` работает), проверка использует резервный источник — Atom-ленту релизов, из которой теперь тоже формируется прямая ссылка на Windows-сборку, так что программа скачивает обновление самостоятельно и не открывает страницу релиза в браузере.
- **Быстрый запуск при большом списке баз** (Windows): главное окно отрисовывается сразу, а построение дерева групп, назначение избранного и восстановление последнего выделения выполняются в фоне с индикатором прогресса — интерфейс не «зависает» при тысячах баз. Размеры файловых ИБ **кешируются** между запусками (`settings.json`) и пересчитываются только при изменении базы, поэтому повторные запуски быстрее.

## ✨ Возможности

### 🚀 Запуск информационных баз
- Запуск базы в режиме **«1С:Предприятие»** и **«Конфигуратор»**.
- **Свободно назначаемые горячие клавиши** (Настройки → Клавиши), как в конфигураторе 1С: 1С:Предприятие, Конфигуратор, Избранное, Изменить, Удалить, Очистить кэш, Добавить базу, Закрепить (по умолчанию `F3` / `F4`). Для назначения достаточно установить курсор в поле и нажать сочетание — поддерживаются **Ctrl, Shift, Alt, Win** (например `Ctrl+Shift+F`), а также F2–F12, Delete, Insert; `Backspace`/`Delete` сбрасывают, `Esc` отменяет ввод. Отображаются на кнопках правой панели и в контекстном меню.
- **Горячие клавиши вкладок списка баз** — отдельные комбинации для переключения **Все базы / Избранное / Недавние** (задаются в **Настройки → Клавиши**).
- **`Ctrl+F`** — фокус в поле поиска (с выделением текущего текста) из любого места главного окна.
- **Горячие клавиши избранного** — `Alt+1`…`Alt+9`: при добавлении в избранное назначается свободный слот; порядок слотов настраивается в окне настроек.
- Выбор типа клиента: **тонкий** / **толстый**, режим **веб-клиента** (доступен только при подключении базы через **веб-сервер**).
- **Толстый клиент разделён по режиму форм** в настройках базы (вкладка **«Запуск»**): **«Толстый клиент (управляемые формы)»** (`/RunModeManagedApplication`) и **«Толстый клиент (обычные формы)»** (`/RunModeOrdinaryApplication`). Это решает случай, когда база на управляемых формах запускалась в обычных.
- **Разрядность запуска** по документации 1С — 4 режима: приоритет 32 (x86) / приоритет 64 (x86-64) / только 32 / только 64; при приоритетных режимах лаунчер выбирает более новую установленную версию между 32/64.
- **Разрядность по умолчанию** в **Настройки → Платформы**: если у базы не указана собственная разрядность, запуск выполняется выбранной разрядностью (**64 бит** по умолчанию или **32 бит**). Применяется к запуску «1С:Предприятие», «Конфигуратор», пакетным операциям и ярлыкам.
- **Разделение «Толстый клиент» по режиму форм в «Текущей сессии»** в правой панели — по аналогии с настройками подключения базы 1С: **«Толстый (управляемые формы)»** (`/RunModeManagedApplication`) и **«Толстый (обычные формы)»** (`/RunModeOrdinaryApplication`). Выбор применяется только к следующему запуску «1С:Предприятие», настройки базы при этом не изменяются.
- Автопоиск установленной платформы 1С (лаунчер `1CEStart.exe` или `1cv8.exe` / `1cv8c.exe`).
- Запуск **конкретной версии** платформы, заданной для базы.
- **Окно выбора версии платформы** как в стартере 1С: дерево **полностью разворачивается** при открытии, свежие версии **по умолчанию сверху** (сортировка по убыванию, переключение иконками как в главном окне), **текущая версия базы подсвечивается жирным** и автоматически позиционируется. Если у базы указана **частичная версия** (`8.3`, `8.3.19` или с разрядностью `8.3 (64)`), выбирается **максимальная доступная сборка** — как это делает сам лаунчер 1С.
- **Дополнительные папки платформ** (Настройки → Платформы): версии из нестандартных/портативных каталогов установки (произвольная вложенность без обязательного подкаталога `1cv8`) находятся, показываются в списке и **корректно запускаются** — и для конкретной версии базы, и при выборе новейшей установленной версии, и в приоритетных режимах разрядности.
- **«Перейти по ссылке»** в правой панели — аналог одноимённой функции стандартного загрузчика 1С: вставьте ссылку на базу (`e1c://...`, `C:\1C\База`, `server\База`, `http://server/base`) и запустите её в «1С:Предприятие».
- **Конфигуратор параметров запуска** — окно «Параметры запуска» устроено как **поле ввода + справочник**: вверху — поле ввода параметров командной строки, ниже — справочник всех ключей запуска 1С с описанием, что делает параметр. Двойной клик по строке справочника подставляет параметр в поле ввода (`/UC`, `/DisableStartupMessages`, `/Debug` и др.).
- **Глобальная настройка «После запуска базы или конфигуратора»** (обе платформы) в **Настройки → Настройки**: сразу после успешного запуска информационной базы или конфигуратора 1С окно приложения можно **свернуть в трей** или **закрыть программу** (полностью завершить работу приложения); значение «Ничего» (по умолчанию) оставляет окно как есть. Работает для запуска из главного окна, по горячим клавишам избранного и из меню трея.

### 👥 Учётные записи (профили)
- **Несколько учётных записей в одном приложении**. Каждая учётная запись (профиль) имеет собственные настройки интерфейса и собственный список информационных баз и групп — файлы данных (`settings.json`, `infobases.json`, `groups.json`) хранятся в подкаталоге профиля внутри каталога данных приложения.
- **Создание и управление профилями** — во вкладке **«Учётные записи»** окна настроек (Windows; на Linux — через кнопку «Управление учётными записями…»): создать новую запись, переименовать, удалить (с подтверждением), а также установить или снять пароль через флажок «Защитить паролем».
- **Дружелюбный интерфейс управления**: вкладка устроена как «список + редактор» — слева список учётных записей (у активной — бейдж **«активная»**), справа панель редактирования выбранной записи с заголовком **«Редактирование записи: <имя>»**. Вверху — **выпадающее меню «Активная учётная запись»** для быстрого переключения активной записи, а кнопка **«Сделать активной»** помечает выбранную запись активной. Так сразу видно, какая запись редактируется, а какая активна.
- **Окно входа как в 1С**. Если в приложении создана одна учётная запись — при запуске вход выполняется сразу, без запроса данных. Если записей несколько — показывается окно выбора учётной записи: для защищённой паролем запрашивается пароль (при неверном вводе выводится ошибка), для незащищённой — вход сразу. При отмене выбора приложение завершается.
- **Безопасное хранение пароля**: пароль профиля хэшируется алгоритмом **PBKDF2-SHA256 со случайной солью** и никогда не сохраняется открытым текстом.
- **Плавная миграция**: при первом запуске после обновления существующие настройки, базы и группы автоматически переносятся в профиль по умолчанию «Пользователь», поэтому данные не теряются.
- **Надёжная загрузка старых конфигурационных файлов** (issue #64): при запуске обновлённой версии поверх легаси-`settings.json`/`groups.json` приложение не «зависает» — `null`-поля коллекций настроек автоматически восстанавливаются до безопасных значений, а циклические ссылки между группами разрываются и сразу сохраняются на диск, поэтому интерфейс гарантированно открывается без ручного удаления конфигов и повторного импорта.

### 🌍 Локализация
- **Многоязычный интерфейс**: **русский** и **английский** из коробки; выбор языка в настройках (применяется сразу), автоопределение по языку ОС при отсутствии явного выбора.
- **Загрузка других языков без пересборки**: достаточно положить `*.json` (формат как у встроенных) в папку `Languages` рядом с приложением или в каталог данных — язык появится в списке выбора.
- При отсутствии перевода строки выполняется откат (английский → русский → ключ), поэтому интерфейс не «ломается» при неполном переводе. Подробнее — [`Localization/README.md`](Configuration Management/Localization/README.md).
- Полностью локализованы диалоговые окна **«Создание информационной базы»** ([`CreateInfobaseWindow.xaml`](Configuration Management/CreateInfobaseWindow.xaml)) и **«Удаление информационной базы»** ([`DeleteInfobaseWindow.xaml`](Configuration Management/DeleteInfobaseWindow.xaml)), компонент **`?`-подсказки** ([`HelpLink.xaml`](Configuration Management/Controls/HelpLink.xaml)), остатки главного окна (подсказки `HelpLink`, строка «Нет выбора») и **текст-заглушка поля поиска** во всех темах ([`DarkTheme.xaml`](Configuration Management/Themes/DarkTheme.xaml), [`LightTheme.xaml`](Configuration Management/Themes/LightTheme.xaml)). Добавлены ключи `HelpLink.*`, `DeleteInfobase.*`, `CreateInfobase.*`, `Main.*` в [`ru.json`](Configuration Management/Localization/Languages/ru.json) и [`en.json`](Configuration Management/Localization/Languages/en.json).
- Дополнительно локализованы оставшиеся строки в Avalonia-контролах и код-бихайндах окон настроек: компонент **`?`-подсказки** (`HelpLink.Avalonia.cs`), поле горячей клавиши **`HotkeyBox`** (WPF и Avalonia), радио сортировки «А → Я» / «Я → А» в окнах **«Выбор группы»** ([`GroupPickerWindow.Avalonia.cs`](Configuration Management/GroupPickerWindow.Avalonia.cs)) и **«Выбор версии платформы»** ([`PlatformVersionPickerWindow.Avalonia.cs`](Configuration Management/PlatformVersionPickerWindow.Avalonia.cs)), «Авто» разрядности сессии и названия начертаний шрифта и встроенных тем в окне настроек. Добавлены ключи `Common.SortAsc/SortDesc`, `Hotkey.Tooltip`, `Theme.Light/Dark`, `Settings.Font.Style*` в [`ru.json`](Configuration Management/Localization/Languages/ru.json) и [`en.json`](Configuration Management/Localization/Languages/en.json).
- Локализованы **диалоговые сервисы** ([`IDialogService.cs`](Configuration Management/Services/IDialogService.cs), [`WpfDialogService.cs`](Configuration Management/Services/WpfDialogService.cs), [`AvaloniaDialogService.cs`](Configuration Management/Services/AvaloniaDialogService.cs)): заголовки сообщений и подтверждений (`Common.Information/Warning/Error/Confirm`), заголовки файловых диалогов (`Dialog.OpenFile/SaveFile/SelectFolder`), фильтр «Все файлы (*.*)» (`Common.AllFiles`) и кнопка «Отмена» (`Common.Cancel`). **Точки входа приложения** ([`App.xaml.cs`](Configuration Management/App.xaml.cs), [`App.axaml.cs`](Configuration Management/App.axaml.cs)): фатальные сообщения через ключи `App.Fatal.*`. Значения по умолчанию параметров интерфейса переведены на пустые строки — локализованный заголовок подставляется в реализациях.

Ключи `Infobase.*`, `Group.*`, `Color.*` добавлены в [`ru.json`](Configuration Management/Localization/Languages/ru.json) и [`en.json`](Configuration Management/Localization/Languages/en.json).
- **Локализованы специальные узлы дерева групп** — «Закреплённые», «Все базы» и «Без группы» ([`GroupNodeViewModel.cs`](Configuration Management/ViewModels/GroupNodeViewModel.cs), [`GroupNodeViewModel.Avalonia.cs`](Configuration Management/ViewModels/GroupNodeViewModel.Avalonia.cs), [`MainViewModel.cs`](Configuration Management/ViewModels/MainViewModel.cs), [`MainWindow.xaml.cs`](Configuration Management/MainWindow.xaml.cs)). - Локализовано **сообщение исключения «Резервная копия не найдена.»** ([`IbasesBackupService.cs`](Configuration Management/Services/IbasesBackupService.cs)): текст подставляется в ошибку восстановления резервной копии (`Settings.Ibases.RestoreFailed`) через новый ключ `Settings.Ibases.BackupNotFound`. ### 💾 Резервное копирование и восстановление профиля
- **Сохранение всех настроек в произвольный каталог и восстановление после переустановки системы** (обе платформы): вкладка **«Резервное копирование»** в окне настроек позволяет одной кнопкой сохранить весь «профиль» приложения — настройки интерфейса (`settings.json`), список информационных баз вместе с **пользователями и паролями запуска** (`infobases.json`), дерево групп (`groups.json`) и стандартный файл списка баз 1С `ibases.v8i`. ### 🗂️ Управление списком баз
- **Вкладки фильтра**: **Все базы**, **Избранное**, **Недавние** (по дате последнего запуска).
- Иерархический список с группами, закреплёнными базами и узлом «Без группы».
- Колонки: наименование, версия платформы, режим запуска, сервер/база, последний запуск, размер; **видимость и порядок колонок настраиваются в одном списке** в **Настройки → Отображение → Колонки** (на обеих платформах): у каждой строки — переключатель видимости (на Windows — тумблер справа), а порядок меняется **кнопками со стрелками ↑/↓ справа от списка** (на обеих платформах, как во вкладке «Клавиши»); колонка «Действия» (как и остальные данные) участвует в настраиваемом порядке и может быть перемещена пользователем, а также **скрыта** через переключатель видимости — закреплена только колонка «Название»; **ширину любой колонки можно изменять** перетаскиванием разделителя на её правой границе (данные и заголовок двигаются синхронно); по умолчанию колонка «Конфигурация» стоит в самом конце. При вложенных группах **колонки данных остаются выровненными с заголовками**; сдвигается только блок ★ / 📌 / название (под иконкой родительской группы).
- **Отображение разрядности рядом с версией платформы** в списке баз (issue #101): если у базы разрядность выбрана явно (`x86`/`x64`), в колонке «Версия платформы» выводится суффикс `[x86]`/`[x64]` — например `8.3.19 [x86]`, `8.3 [x64]`. При автоопределении или приоритетном режиме показывается только чистая версия (`8.3.27.2325`), как раньше. Двойной щелчок по колонке по-прежнему открывает окно выбора версии платформы.
- **Цветные иконки статуса баз** слева от названия показывают тип подключения и доступность базы: папка **янтарного** цвета — файловая база, глобус **синего** цвета — база на веб-сервере, сеть **фиолетового** цвета — клиент-серверная база, **красный крест** — база недоступна (для файловых — каталог/`1Cv8.1CD` не найден на диске; для клиент-серверных и веб-баз — не заполнены параметры подключения). При наведении на иконку показывается подсказка со статусом. Сетевая доступность удалённо не проверяется автоматически, чтобы не блокировать интерфейс.
- **Кнопка «Доступность» (иконка-сонар) в верхней панели команд** (обе платформы): по нажатию проверяет доступность всех баз по факту и сразу обновляет их иконки в списке — недоступные базы помечаются красным крестиком. Для файловых баз доступность определяется наличием каталога/файла по пути, для клиент-серверных — реальной попыткой подключения через COM-коннектор, для веб-баз — заполненностью адреса. Проверка выполняется в фоне, чтобы не блокировать интерфейс; после завершения в **нижней строке состояния** на 10 секунд показывается сообщение «Проверка доступности: всего {0}, недоступно {1}».
- **COM-коннектор 1С вынесен в отдельный процесс-агент** (Windows/WPF; авторство — [ksv47](https://github.com/ksv47), PR #69): чтение сведений о конфигурации 1С больше не выполняется в процессе приложения. Это устраняет молчаливое завершение на старте с кодом **0xC0000409** — прямой COM-вызов `comcntr.dll` под CoreCLR обрывал процесс нативным fast-fail без управляемого исключения. Агент обслуживает запросы по протоколу `stdin`/`stdout`, пароль в командную строку не попадает; текст ошибки 1С скрывается, если у базы задан пароль; строка подключения экранируется; таймаут честный, диагноз сохраняется даже при гибели агента; добавлена поддержка платформы 8.5 в переборе ProgID. Прямой COM-вызов в текущем процессе запрещён (метод помечен `[Obsolete]`). Логика агента покрыта юнит-тестами в [`Configuration Management.Tests`](Configuration Management.Tests/).
- **Сортировка по клику** на заголовки колонок (название, дата и др.).
- Добавление, редактирование и удаление баз; мастер «Что добавить?» (база или группа).
- **Избранное** (★) и **закрепление** (📌) — в колонке названия строки базы (действуют на конкретную базу этой строки); команды добавить/правка/удалить, очистка кеша, синхронизация и настройки — на панели команд над заголовками колонок (Windows/WPF; «Правка» и «Удаление» действуют на выбранную базу); закреплённые — в отдельной группе сверху.
- **Поиск** по имени, описанию, группе, версии и тегам (с debounce, без «тормозов» на каждый символ).
- **Теги**: инлайн-добавление в строке базы, компактные чипы, удаление крестиком, **мультифильтр** (несколько тегов сразу) и облако тегов на панели отбора.
- Во вкладках **«Избранное»** и **«Недавние»**, при **отборе по тегу** и при **поиске** группы и закреплённые базы **временно скрываются** — показывается единый плоский список найденных баз, что исключает дубли (закреплённая база раньше попадала и в «Закреплённые», и в свою группу). При возврате к вкладке «Все базы» дерево групп и закрепления восстанавливаются.
- Перетаскивание баз и групп; сворачивание/разворачивание всех групп с верхней панели.
- **Значок тега** в строке заголовка списка (слева от колонки «Название») включает/выключает **только теги в строках списка баз** и не затрагивает панель быстрого отбора тегов. **Верхняя кнопка «Показывать теги»** на верхней панели включает/выключает и **панель тегов сверху** (облако тегов), и **теги в списке баз**; её состояние отражает видимость панели тегов сверху и остаётся включённой, пока панель тегов отображается. Панель также управляется настройкой в окне настроек. При **отключении показа тегов** верхней кнопкой выбранные теги **фильтра списка баз** автоматически **сбрасываются**, чтобы отбор по тегу не продолжал скрывать базы.
- **Навигация стрелками** по списку: `↑`/`↓` — переход по строкам (базам и группам), `←`/`→` — сворачивание/разворачивание выбранной группы. Стрелки всегда управляют выделением в дереве и не перескакивают на кнопки внутри строки.
- **Приложение запоминает последнюю выделенную строку списка** (базу или группу) и восстанавливает её при следующем запуске.
- **Запоминание окна**: приложение запоминает размер, позицию, состояние и **монитор**, на котором было закрыто главное окно, и восстанавливает их при следующем запуске. При нескольких мониторах окно снова открывается на том же экране. Настройка **«Запоминать расположение, размер и монитор окна»** находится в **Настройки → Настройки → Поведение приложения**; при отключении окно при запуске открывается по центру экрана.

### 🏷️ Группы
- Вложенные группы («группа в группе») с **наглядным смещением** кнопки разворота и заголовков групп по глубине вложенности — всегда видно, какая группа находится внутри другой, а также цвет и **иконка** группы. Названия баз с ★/📌 располагаются под иконкой папки родительской группы; колонки данных не смещаются.
- **Сортировка групп по имени** кнопками на панели команд над заголовками колонок (рядом с «Развернуть/Свернуть все группы»): **по возрастанию (А→Я)** и **по убыванию (Я→А)**. Кнопки в стиле **Material Design** сортируют подгруппы рекурсивно, включая вложенные группы; направление запоминается и применяется при перестройке дерева.
- В правой панели при выборе группы отображается **выбранная иконка**.
- Создание, редактирование, удаление; **выбор родительской группы** — в окне, оформленном как выбор версии платформы (зелёная «Выбрать», «Отмена» с красной обводкой, двойной щелчок — подтверждение), где у каждой группы виден её **цвет** и **иконка** из настроек группы (иконка отображается на цвете самой группы — как в списке баз, поэтому видна в обеих темах); сделать группу корневой можно пунктом «Корневая группа».
- **Окно выбора группы говорит нейтрально о «выбранном элементе»**, а не только о группе: оно открывается и при создании информационной базы, и в настройках её подключения (не только при настройке группы), поэтому заголовок, подзаголовок и справка используют общую формулировку «выбранный элемент» (issue #83). Обе реализации — [`Views/GroupPickerWindow.xaml`](Configuration Management/Views/GroupPickerWindow.xaml) на Windows/WPF и [`Views/GroupPickerWindow.Avalonia.cs`](Configuration Management/Views/GroupPickerWindow.Avalonia.cs) на Linux/Avalonia — читают одни и те же ключи локализации `GroupPicker.Title/Subtitle/Help`. В Windows/WPF текст выбирается по виду объекта (группа/база) через enum `GroupPickerObjectKind` (`Group`/`Infobase`), который передаётся в конструктор окна: при выборе родительской группы для группы используются ключи `GroupPicker.TitleGroup/SubtitleGroup/HelpGroup`, а при выборе группы для информационной базы — `GroupPicker.TitleBase/SubtitleBase/HelpBase` (issue #83, части 1–2). Все WPF-точки вызова теперь передают нужный вид: при создании базы ([`CreateInfobaseWindow.xaml.cs`](Configuration Management/Views/CreateInfobaseWindow.xaml.cs)) и настройке подключения базы ([`ConnectionSettingsWindow.xaml.cs`](Configuration Management/Views/ConnectionSettingsWindow.xaml.cs)) — `Infobase`, а при настройке группы ([`GroupEditWindow.xaml.cs`](Configuration Management/Views/GroupEditWindow.xaml.cs)) — `Group` (issue #83, часть 3).
- Окно группы разделено на **горизонтальные вкладки** «Основные / Цвет / Иконка» по аналогии с окном настроек; кнопки «Сохранить»/«Отмена» всегда закреплены внизу (зелёная «Сохранить», «Отмена» с красной обводкой). Высота окна автоматически подстраивается под содержимое активной вкладки, чтобы **все данные помещались на экран**.
- **Группы без названия** (например, импортированные из `ibases.v8i`) можно создавать и редактировать; в дереве такие группы отображаются как «Без названия».
- **Пустые группы** (без баз) отображаются в дереве в правильной иерархии — внутри своей родительской группы. Переключатель рядом с «показывать группы» на верхней панели и в **Настройки → Отображение → Панели**.
- Служебные узлы **«Закреплённые»** и **«Без группы»** имеют собственное оформление по умолчанию, отличающееся от обычных групп: закреплённые — фиолетовый цвет, «Без группы» — серый. Кнопка **«Удалить группу»** у них скрыта. Оформление обоих узлов меняется через **«Изменить группу»** (кнопка в строке узла или горячая клавиша правки) — открывается то же окно (вкладки **Основные / Цвет / Иконка**), но поля **«Наименование»** и **«Родительская группа»** заблокированы. Изменения сохраняются в настройках приложения.

### 🔄 Импорт, экспорт и синхронизация

- **Синхронизация** с `ibases.v8i`: отключена / только загрузка / только выгрузка / двусторонняя; триггеры — при старте, по интервалу, по расписанию.
- Экспорт / импорт списка в **JSON**; очистка всего списка с подтверждением.
- Автосопоставление **ID (GUID)** базы из `ibases.v8i` для точечной очистки кеша.
- **Резервные копии `ibases.v8i`** перед синхронизацией/экспортом (`ibases.v8i.bak_yyyyMMdd_HHmmss`), хранение N последних копий, кнопка «Восстановить из последней копии» в настройках синхронизации.

### 🧹 Очистка кеша 1С
- Очистка локального кеша платформы для выбранной базы по GUID (программный и/или пользовательский).
- **В окне «Очистка кэша» рядом с типами кеша показывается их текущий размер** — «Программный кэш (1,2 ГБ)», «Пользовательский кэш (340 МБ)». Размер вычисляется асинхронно по содержимому корневых каталогов кеша (на Windows `%LOCALAPPDATA%\1C\1cv8…` и `%APPDATA%\1C\1cv8…`; на Linux `~/.cache/1cv8`, `~/.local/share/1cv8`, `~/.1cv8/1cv8`) и отображается в человекочитаемом виде с единицами, зависящими от языка интерфейса (Б/КБ/МБ/ГБ/ТБ или B/KB/MB/GB/TB).
- **Для каждой базы в списке окна показаны две колонки с размером её кеша — «Программный» и «Пользовательский».** Это позволяет сразу оценить, какая база занимает больше всего места, ещё до очистки.
- **Размер кеша выбранной базы отображается в правой панели главного окна** (строка **«Размер кеша»** в блоке сведений о подключении) на обеих платформах (Windows/WPF и Linux/Avalonia). Значение вычисляется асинхронно в фоновом потоке при выборе базы и показывается в человекочитаемом виде; пока размер не определён, выводится «…».
- **Очистка «остатков» кеша от удалённых баз** — чекбокс **«Остатки от удалённых баз»** с индикатором занимаемого размера в нижней части окна. Он показывает каталоги кеша, не соответствующие ни одной текущей информационной базе (остались после удаления базы из списка или переноса её в другое приложение), и при включении удаляет их вместе с кешем выбранных баз. Очистку остатков можно выполнить и без выбора конкретных баз. Подпись чекбокса **переносится на несколько строк и читается целиком даже при минимальной ширине окна**: чекбокс занимает всю доступную ширину нижней панели (колонка `*`), надпись не обрезается (`TextWrapping=Wrap`), справа остаются размер и кнопки «Очистить»/«Отмена» (обе платформы).
- **Шапка колонок списка закреплена вверху** и остаётся видимой при прокрутке. **Ширину любой колонки можно изменить**, перетаскивая узкую зону захвата на её правой границе (как в главном окне); изменяется только выбранная колонка. Ширины запоминаются при закрытии окна и восстанавливаются при следующем открытии.
- **Split-кнопка «Очистка кеша»** в секции «Обслуживание» правой панели — по аналогии с кнопкой запуска «1С:Предприятие»: прямое нажатие открывает окно очистки кеша, а стрелка «▾» справа открывает выпадающее меню («Открыть окно очистки кеша…», «Программный кеш…», «Пользовательский кеш…», «Программный и пользовательский»). Кнопка доступна даже при выбранной группе: тогда окно очистки открывается без выделенной базы в списке; при выбранной базе она выделяется в окне по умолчанию.

### 🛠️ Создание информационных баз
- Создание ИБ через `CREATEINFOBASE`: пустая база или **из шаблона** (.cf / .dt). Поддерживаются **файловые** и **клиент-серверные** базы. Для клиент-серверного варианта задаются сервер 1С (`Srvr`), имя базы на сервере (`Ref`) и при необходимости параметры СУБД: тип (`DBMS`), сервер СУБД (`DBSrvr`), имя базы данных (`DB`), пользователь и пароль (`DBUID`/`DBPwd`), опция создания БД на сервере СУБД (`CrSQLDB="Y"`) и галочка **«Блокировка фоновых заданий»** (`SchJobDn="Y"`, задаётся только при создании базы). **Авторство правок — [ksv47](https://github.com/ksv47)** (PR #108, ветка `ksv47/fix-issues-90-94`): пароль СУБД (`DBPwd`) маскируется (заменяется на `********`) в сообщениях об ошибке `CREATEINFOBASE` — и в показанной команде, и в диагностике платформы, если она повторила строку подключения.
- **Надёжное экранирование** (обе платформы, issue #77): значения в строке подключения `CREATEINFOBASE` и в записи `ibases.v8i` экранируются по правилу 1С (кавычка удваивается) и симметрично разворачиваются при обратном разборе, а значения, подставляемые в аргументы командной строки платформы (`/F`, `/S`, `/WS`, `/N`, `/P`, `/UseTemplate`, `/DumpIB`, `/DumpCfg` и др.), защищены от внедрения дополнительного ключа `1cv8` — небезопасное значение (содержащее кавычку или управляющий символ) не подставляется, а создание из шаблона или выгрузка отменяется с понятным сообщением. Пробелы в значениях сохраняются.
- **Шаблоны конфигураций** — список установленных конфигураций из стандартных каталогов `tmplts` (разбор `1cv8.mft`, как в стартере 1С), группировка в дереве, либо выбор файла вручную. Дерево шаблонов строится **в фоне**, поэтому окно открывается сразу даже на больших каталогах (`~1100` манифестов), а список дособирается по готовности (во время загрузки показывается индикатор). Подсказка каталога отражает фактически используемый источник шаблонов (с учётом своих каталогов из Настроек), а не дефолтный `tmplts`. Выбор шаблона начинается **пустым** — имя базы и путь к файлу заполняются только после явного выбора шаблона в дереве.
- **Поле «Версия» по умолчанию подставляется последней успешно использованной версией платформы** (обе платформы, issue #91), а не самой новой из установленных — отдельно для файловых и клиент-серверных баз. Версия запоминается только после успешного создания базы; если сохранённой версии больше нет среди установленных, берётся самая новая. Это снимает типовую проблему клиент-серверных баз, когда версия клиента должна совпадать с версией сервера 1С. **Поле корректно обновляется и при переключении типа базы** между файловой и клиент-серверной (в окне всегда открыт файловый тип) — подставляется последняя успешная версия для выбранного типа. **Авторство правок — [ksv47](https://github.com/ksv47)** (PR #109, ветка `ksv47/fix-issue-91`).
- **Предупреждение о несоответствии версии платформы** (обе платформы, issue #91): при создании клиент-серверной базы, если выбранная версия отличается по первым двум числам (major.minor) от версий, которыми уже работают базы на этом же сервере, показывается предупреждение с возможностью продолжить создание. Раньше о несовместимости пользователь узнавал только по отказу платформы.
- **Настройка каталогов шаблонов** в Настройки → Базы (приоритет пути из настроек стартера 1С), кнопка «Из 1С».

### 📦 Обслуживание баз
- **История запусков** (до 30 записей на базу) — пополняется при запуске/выгрузке/тесте, просмотр из контекстного меню.
- **Выгрузка `.dt` / `.cf`** и **тестирование ИБ** (`/IBCheckAndRepair -TestOnly`) через пакетный `DESIGNER`.
- **Анимированный индикатор выгрузки** в верхнем правом блоке кнопок, слева от кнопки синхронизации: иконка-стрелка вверх (выгрузка файла) появляется при запуске выгрузки `.dt` / `.cf`, анимируется (подпрыгивает) до её завершения и автоматически исчезает. При наведении на индикатор показывается **сводка о текущей выгрузке** — операция, имя базы и путь к файлу.
- **Дата-время в имени файла выгрузки** (экспорт списка в **JSON**, выгрузка ИБ в **`.dt`**, выгрузка конфигурации в **`.cf`**): в имя файла автоматически добавляется отметка времени (например `База_20260819_074312.dt`). Включается/выключается флажком **«Добавлять дату-время к имени файла при выгрузке»** в **Настройки → Базы → Список информационных баз** (включён по умолчанию). **Формат отметки настраивается**: рядом с флажком есть выпадающий список **«Шаблон даты и времени»** с предпросмотром примера — можно выбрать готовый шаблон (например `yyyy-MM-dd_HH-mm-ss` → `База_2026-08-19_07-43-12.dt`) или ввести собственный формат `DateTime`.
- **Открыть каталог** файловой базы в проводнике; **ярлык на рабочем столе** (как у стандартного стартера 1С).
- **Удалить отсутствующие файловые базы** (нет каталога / `1Cv8.1CD`) и **завершить процессы 1С** (1cv8, 1cv8c и др.) — Настройки → Базы → Обслуживание.
- Колонка **«Размер»** для файловых ИБ (видимость настраивается в Отображение → Колонки).
- **Удаление ИБ** с опцией **«Физически удалить каталог базы с диска»** (только файловые, с повторным подтверждением).

### 🪟 Системный трей и поведение
- Значок в трее, **закрытие в трей**, восстановление окна двойным кликом.

- Контекстное меню трея: **недавние базы** (до 7) с подменю «1С:Предприятие / Конфигуратор», синхронизация ibases, настройки, выход.

- Вкладка «Отображение»: подвкладки (Значки и кнопки, Колонки списка, Панели, Нижняя панель) с тумблерами видимости элементов.

- Вкладка «Настройки»: поведение приложения (несколько экземпляров, значок в трее, сворачивание, `Esc` → трей).
- Вкладка «Платформы»: группировка по линии **8.3 / 8.5** и **разрядности** (64/32) с путями установки, **дополнительные пути поиска** платформы.
- Вкладка «Базы»: каталоги шаблонов, экспорт/загрузка списка баз, обслуживание (удаление отсутствующих баз, завершение процессов 1С).
- Вкладка «О программе»: автор, Infostart, GitHub.
- Кнопки **Сохранить** (зелёная) и **Отмена** (красная обводка) — единый стиль диалогов.
- Окно **настроек подключения к базе** оформлено в том же стиле (шапка, те же кнопки) с **вертикальными вкладками слева** — **База / Подключение / Хранилище / Авторизация / Запуск / Разрядность / Платформа / Идентификатор**; каждая вкладка содержит один логический блок, содержимое прокручивается по вертикали при нехватке места. Поле **«Сервер»** на вкладке «Подключение» — выпадающий список с серверами 1С из других клиент-серверных баз списка (можно выбрать или ввести вручную). Поле **«Порт сервера»** — такой же **редактируемый выпадающий список** с портами из существующих клиент-серверных баз (без дублей, по возрастанию): удобно, когда сервер один, а инстансы висят на разных портах.
- **Вкладка «Хранилище»** — хранение адреса сервера, имени, логина и пароля для подключения к хранилищу конфигурации 1С ([`RepositorySettings`](Configuration Management/Models/RepositorySettings.cs)).
- **Вкладка «Авторизация»** содержит две независимые настройки: **«Авторизация в 1С:Предприятие»** (пользователь и пароль для запуска клиента, например тестовый пользователь) и **«Авторизация в Конфигураторе»** (отдельные учётные данные для запуска Конфигуратора, «под собой»). Обе настройки хранятся отдельно и независимо ([`Infobase.EnterpriseAuth`](Configuration Management/Models/Infobase.cs) и [`Infobase.ConfiguratorAuth`](Configuration Management/Models/Infobase.cs)) и **не копируются** друг из друга. При запуске «1С:Предприятие» применяется авторизация Предприятия, при запуске Конфигуратора — авторизация Конфигуратора; для баз, сохранённых до появления этих настроек, используется авторизация базы (обратная совместимость).
- **«Вставить строку подключения»** — кнопка **на вкладке «Подключение»** окна настроек базы (доступна при создании новой базы и при правке свойств, **только на этой вкладке**). По клику открывается **окно ввода строки подключения** с полем для ввода и кнопкой **«Вставить из буфера»**; если в буфере обмена лежит строка, удовлетворяющая критериям ссылки на базу 1С (строка подключения с `Srvr`/`Ref`/`File`/`WS`, ссылка-протокол `e1c://`, веб-адрес `http(s)://`, путь к файловой базе или `server\base`), она **автоматически подставляется** в поле. Кнопка **«Применить»** разбивает строку по полям — тип подключения, сервер/порт, имя базы, путь файла или URL веб-публикации, пользователь и пароль. Если наименование базы не задано, подставляется имя базы (`Ref`) или каталога файловой базы. При открытии свойств существующей базы поле заполняется её текущей строкой подключения.

### 🎨 Интерфейс
- **Гиперссылки-вопросы «?»** — круглый значок «?» рядом с ключевыми и неочевидными элементами форм. По клику открывается всплывающая подсказка, которая объясняет поведение элемента и как с ним взаимодействовать (закрывается повторным кликом или кликом в любом другом месте окна). Такие подсказки добавлены в главное окно, список баз, панель тегов, настройки (клавиши, синхронизация), настройки подключения базы, мастер добавления, окна группы/выбора родителя, создание/удаление ИБ и конфигуратор параметров запуска.
- **Кнопка справки «?» в окне выбора родительской группы больше не уезжает за край окна** (Windows/WPF): текст пояснения переносится по ширине, а кружок «?» прижат к правому краю верхней строки и доступен даже при размере окна по умолчанию ([`Views/GroupPickerWindow.xaml`](Configuration Management/Views/GroupPickerWindow.xaml)).
- **Светлая** и **тёмная** темы; переключение с главного окна, а также полноценное **цветовое оформление** в **Настройки → Цветовое оформление**: выбор темы (встроенные «Светлая»/«Тёмная» и собственные), изменение отдельных цветов интерфейса (акцент, боковая панель, фон карточек, текст, границы, строки, полосы прокрутки и др.) с предпросмотром, создание/переименование/удаление своих тем, **выгрузка и загрузка цветовых схем** в JSON-файл. Изменения применяются сразу, активная схема сохраняется в настройках.
- **Верхняя строка** (Windows/WPF) содержит переключатели **группировки/тегов**, поле **поиска** и **вкладки** «Все/Избранное/Недавние» — остаётся сверху левой колонки. Над ней можно перетаскивать окно.
- **Панель команд** (Windows/WPF) размещена **внутри левой колонки, над заголовками колонок списка** и занимает всю её ширину, не накладываясь на правую панель: «Управление группами» (развернуть все · свернуть все · сортировка А→Я · Я→А · отображение тегов) · затем смысловые группы через тонкие вертикальные разделители — «Правка» (добавить · правка · удаление), «Управление списком» (очистка кеша · индикатор выгрузки · синхронизация ibases · проверка доступности) и «Настройки» (тема · компактный режим · настройки · справка). Кнопки «Правка» и «Удаление» работают по выбранной базе и недоступны, когда ничего не выбрано; кнопки «Избранное» и «Закрепление» расположены в колонке названия каждой строки базы.
- **Правая панель**: карточка базы или группы, действия запуска с отображением хоткеев, изменение, избранное, закрепление, очистка кеша, удаление. Блок **«Текущая сессия»** — режим клиента и разрядность без изменения настроек базы.
- **Компактный режим** правой панели — только кнопки действий (ширина по содержимому).
- **Нижняя панель** (статус): путь/сервер, порт, платформа, разрядность, режим запуска, тип клиента, тип подключения, пользователь, ID базы (настройка видимости).
- Современные стили кнопок, ComboBox, GroupBox; виртуализация списка для больших каталогов баз.
- **Радиокнопки (RadioButton) в стиле Material Design** в окне «Выбор версии платформы» ([`PlatformVersionPickerWindow.xaml`](Configuration Management/Views/PlatformVersionPickerWindow.xaml)): округлый индикатор с акцентной заливкой (`AccentBrush`) и мягкой подложкой при наведении — без громоздкой обводки, в едином стиле с остальным UI. Чекбоксы оформляются аналогичным стилем `ModernMaterialCheckBox` из темы.
- **Настройка шрифта интерфейса** в **Настройки → Отображение → Шрифт**: выбор семейства шрифта (Segoe UI, Arial, Calibri, Tahoma, Verdana и др.), размера (как в Microsoft Word — от 8 до 72, размер можно также **ввести вручную**) и начертания (Обычный / Полужирный / Курсив / Полужирный курсив) с предпросмотром. Шрифт можно настроить **отдельно для каждой области**: «По умолчанию», список баз, заголовки списка, правая панель, нижняя панель (статус), вкладки, кнопки, поля ввода. Изменения применяются ко всей программе сразу (кнопка «Применить») и сохраняются кнопкой «Сохранить», а также восстанавливаются при следующем запуске приложения.
- Сохранение размеров окна, темы, свёрнутых групп, настроек отображения и шрифта между запусками.

- **Сняты устаревшие (deprecated) API Avalonia 11** — в окнах очистки кеша, ввода строки подключения, выбора группы и выбора версии платформы события `Checked`/`Unchecked` заменены на `IsCheckedChanged`, а `clipboard.GetTextAsync()` — на `clipboard.TryGetTextAsync()`. Windows/WPF — [`OneCLauncher.Arguments.cs`](Configuration Management/Services/OneCLauncher.Arguments.cs), Linux/Avalonia — [`OneCLauncher.Linux.cs`](Configuration Management/Services/OneCLauncher.Linux.cs). Авторство правок — **[ksv47](https://github.com/ksv47)** (PR #76, ветка `ksv47/fix-createinfobase-escaping`; см. выпуск 0.4.2 в [`CHANGELOG.md`](CHANGELOG.md)).

### 📦 Установка на Linux

Готовые пакеты собираются из single-file публикации и включают `.desktop`-файл и иконку приложения.

#### AppImage (переносимый)

```bash
# 1) Сборка single-file
./build.sh Release publish

# 2) Упаковка в AppImage (нужен appimagetool в PATH)
./package/linux/appimage.sh
```

Результат: `package/linux/out/ConfigurationManagement-x86_64.AppImage`. Запуск:
```bash
chmod +x package/linux/out/ConfigurationManagement-x86_64.AppImage
./package/linux/out/ConfigurationManagement-x86_64.AppImage
```

#### .deb (Debian/Ubuntu/Astra)

```bash
# 1) Сборка single-file
./build.sh Release publish

# 2) Упаковка в .deb (нужен dpkg-deb)
./package/linux/deb/build-deb.sh
```

Результат: `package/linux/deb/out/configuration-management_<версия>_amd64.deb`. Установка/удаление:
```bash
sudo dpkg -i package/linux/deb/out/configuration-management_*_amd64.deb
sudo apt remove configuration-management   # удаление
```

#### .rpm / snap (необязательно)

Формат `.rpm` (для ALT Linux, Fedora) и `snap` поддерживаются на уровне структуры пакета, но скрипты сборки для них пока не реализованы. `.deb`-пакет может быть пересобран для `.rpm` через `alien` при необходимости.

## 🔧 Сборка и запуск

### Из исходного кода

```bash
# Клонирование репозитория
git clone https://github.com/USERNAME/Configuration-Management.git
cd Configuration-Management

# Сборка проекта
dotnet build "Configuration Management/Configuration Management.csproj"

# Запуск
dotnet run --project "Configuration Management/Configuration Management.csproj"
```

Либо откройте файл решения `Configuration Management.slnx` в **Visual Studio 2022+** и запустите проект.

### 📦 Публикация автономного приложения

Проект настроен на публикацию в виде **автономного (self-contained) single-file** исполняемого файла.

**Один исполняемый файл для Windows.** Выделенный скрипт [`build-windows-single-file.ps1`](Configuration Management/build-windows-single-file.ps1) собирает WPF-приложение (`net10.0-windows`, RID `win-x64`) и оставляет в выходной папке **только один файл** `ConfigurationManagement.exe` — без `.dll`, `.pdb` и сопутствующих папок:

```powershell
.\build-windows-single-file.ps1                 # Release, RID win-x64
.\build-windows-single-file.ps1 -RID win-arm64  # другой RID
```

Результат — в каталоге `dist\win-x64\`: единственный исполняемый файл **`ConfigurationManagement.exe`** (self-contained single-file со встроенными нативными библиотеками), который не требует установки .NET Runtime на целевой машине. Скрипт предназначен для запуска на Windows.

Альтернативный вариант через универсальный [`build.ps1`](Configuration Management/build.ps1):

```powershell
.\build.ps1 -Publish
```

либо вручную:

```powershell
dotnet publish "Configuration Management.csproj" -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true
```

## 🔗 Работа с файлом `ibases.v8i`

Приложение взаимодействует со стандартным файлом списка баз 1С `ibases.v8i` (расположен в `%APPDATA%\1C\1CEStart\`):

- **Импорт** — считывает базы, группы, ID (GUID), версию платформы (`Version`), режим запуска (`App`), локаль (`Locale`), признак внешней базы (`External`), скорость соединения (`ClientConnectionSpeed`), признак веб-клиента (`WA`) и дополнительные параметры подключения (`AdditionalParameters`, сохраняются в параметры запуска базы). Поддерживает **иерархию групп**: пути вида «Родитель\Дочерняя» разбираются на сегменты, недостающие родительские группы создаются автоматически. Добавляет новые базы и обновляет существующие.
- **Экспорт** — выгружает базы и группы приложения в файл `ibases.v8i`, добавляя новые записи и обновляя существующие (по совпадению имени базы). Группы записываются секциями без строки подключения, для баз переносятся версия платформы, режим запуска (`App`/`DefaultApp`) и дополнительные параметры запуска. Существующие секции-группы только обновляются (новые при выгрузке не создаются), а дубликаты секций с одинаковым именем устраняются (приоритет — за базой). Строка подключения (`Connect`) всегда завершается знаком «;» (например, `Connect=File="D:\база";`) — это необходимо для корректной работы **EDT** и других средств 1С с базой.
- **Синхронизация** — в окне настроек можно задать режим автоматической синхронизации с файлом `ibases.v8i` (отключена / только загрузка / только выгрузка / двусторонняя) и путь к файлу. Синхронизация выполняется автоматически при изменении списка баз, при запуске приложения, через заданный интервал или по расписанию, а также вручную по кнопкам «Загрузить» / «Выгрузить».
- **Сопоставление ID** — при ручном создании базы приложение автоматически находит её ID в `ibases.v8i` по имени или строке подключения и подставляет его. Это обеспечивает корректную точечную очистку кеша 1С по GUID.
- **Очистка кеша** — использует ID базы (GUID) для удаления только соответствующего подкаталога кеша, а не всего каталога базы.

## 🧩 Архитектура

Приложение построено по паттерну **MVVM**:

- **Models** — описывают доменные сущности (информационные базы, группы, настройки подключения).
- **ViewModels** — содержат логику представления и команды, реализуют `INotifyPropertyChanged`.
- **Views (XAML)** — отвечают за отображение и привязку данных.
- **Services** — инкапсулируют работу с платформой 1С, файловой системой и хранилищем данных.

## Сборка

### Локально (Windows)

```powershell
# Только сборка
.\build.ps1

# Сборка + публикация single-file win-x64
.\build.ps1 -Publish

# Один исполняемый файл ConfigurationManagement.exe (без .dll/.pdb/папок)
.\build-windows-single-file.ps1
```

Результат публикации через `build.ps1` — `publish\win-x64\`; через `build-windows-single-file.ps1` — `dist\win-x64\ConfigurationManagement.exe` (единственный файл в каталоге).

Или вручную:

```powershell
dotnet build "Configuration Management.csproj" -c Release
dotnet publish "Configuration Management.csproj" -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -o .\publish\win-x64
```

> На Windows проект собирается как WPF (`net10.0-windows`); на Linux — как Avalonia (`net10.0`). Целевой TFM и набор компилируемых файлов выбираются автоматически по ОС в [`Configuration Management.csproj`](Configuration%20Management/Configuration%20Management.csproj). Для Linux доступны скрипты `./build.sh`, `./build-linux-single-file.sh` и упаковка в AppImage / `.deb` (см. раздел «🐧 Поддержка Linux»).

### Автоматическая сборка (GitHub Actions)

В репозитории настроен CI-workflow **Build** ([`.github/workflows/build.yml`](.github/workflows/build.yml)): на каждый push в `main`, на pull request и по ручному запуску выполняются две параллельные задачи — **Windows** (WPF, `net10.0-windows`) и **Linux** (Avalonia, `net10.0`). Каждая задача собирает проект в конфигурации **Release** тем же скриптом, что и локально (`build.ps1` / `build.sh`), поэтому CI и ручная сборка не расходятся.

| Workflow | Когда запускается | Что делает |
|----------|-------------------|------------|
| **Build** ([`.github/workflows/build.yml`](.github/workflows/build.yml)) | push в `main`, pull request, вручную | Restore → Build Release на Windows (WPF) и Linux (Avalonia) |

> Для WPF-сборки используется Windows-раннер (`windows-latest`), для Linux-сборки Avalonia — `ubuntu-latest`; обе требуют .NET 10 SDK.
